# Urgency Scoring

## เป้าหมาย

จัดลำดับว่าเหตุใดควรถูกตรวจสอบก่อน ไม่ใช่การวัดความรุนแรงทางวิทยาศาสตร์

## หลักการ

- คะแนนคำนวณใน application code
- ทุก factor มี contribution และ source
- LLM ไม่สร้างหรือแก้คะแนน
- Context เพิ่ม priority แต่ไม่ยืนยันสาเหตุ
- เจ้าหน้าที่ต้องตรวจภาคสนาม

## Demo result

PB-024 ได้ `87/100` ระดับ High จากปัจจัยหลายด้าน เช่น:

- มีรายงานอิสระหลายรายการ
- รายงานเกิดในช่วงเวลาใกล้กัน
- มีสัญญาณปลาตายและกลิ่นผิดปกติ
- อยู่ใกล้พื้นที่อุตสาหกรรมในข้อมูลจำลอง
- อยู่ในบริบทพื้นที่น้ำท่วมในข้อมูลจำลอง

## การแปลผล

| คะแนน | ความหมายใน Prototype |
|---|---|
| ต่ำ | ตรวจตามคิวปกติ |
| กลาง | เฝ้าระวังและรวบรวมข้อมูลเพิ่ม |
| สูง | ควรตรวจสอบภาคสนามโดยเร็ว |
| วิกฤต | ต้องใช้ escalation policy ที่หน่วยงานกำหนด |

Threshold เหล่านี้ยังไม่ผ่านการรับรองทางวิทยาศาสตร์หรือ operational validation

## Required UI notice

> คะแนนจัดลำดับความสำคัญสำหรับ Prototype ไม่ใช่ค่าความรุนแรงทางวิทยาศาสตร์

> Eco-Alert AI ประเมินความเร่งด่วน ไม่ได้ระบุชนิดของสารเคมี
